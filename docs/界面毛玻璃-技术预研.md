| 问题 | 结论 |
| --- | --- |
| 能不能做？ | **能**，且是纯界面层改动：不动引擎、不动注入、不动 ABI（`AbiVersion` 仍 26）、不动 ini。两个 exe 的主程序 + cfg 都可改。 |

## 1. 需求拆解

### 1.1 「高斯模糊半透明」= Acrylic 材质

窗口后方内容（桌面/其他窗口）实时高斯模糊 + 一层半透明染色（tint）+ 轻微提饱和。
这是 Fluent 的 Acrylic，DWM 原生支持（方案 A）。

### 1.2 「液态玻璃」= Acrylic + 五个附加视觉要素

对照 iOS 26 Liquid Glass 与各平台开源实现（cupertino_liquid_glass / LiqUIdify 等，
2026 年核对）拆出可落地的要素清单：

| # | 要素 | 说明 | DWM 能给吗 |
| --- | --- | --- | --- |
| 1 | 镜面高光 specular | 玻璃上缘一条亮线，随光源/鼠标方向偏移 | ✗ |
| 2 | 方向性边缘光 directional edge lighting | 高光非均匀：靠近鼠标的一侧更亮 | ✗ |
| 3 | 内阴影 / 内描边 | 玻璃厚度感：1px 内亮边 + 底部内暗 | ✗ |
| 4 | 噪点纹理 noise | 极低 alpha 颗粒，消除渐变色带 | ✗（acrylic 自带一点，不可控） |
| 5 | 弹性动效 spring | 交互时高光/厚度参数插值（~150ms 回弹） | ✗ |

要素 1-4 是绘制参数，5 是插值器。**都必须自绘** ⇒ 无论背景模糊选哪条路，
玻璃层代码都要写。所以本预研把问题拆成互不阻塞的两半：**背景模糊路径** + **玻璃层**。

## 2. 现状评估（源码核对）

### 2.1 渲染管线：纯 GDI 自绘

- 主程序 `R3ShieldCore/R3ShieldCore/r3shieldcore_gui.cpp`：
  `PaintWindow()`（:3524）→ `CreateCompatibleDC` 内存 DC（:3533）→ 全 GDI 图元
  （`FillRect` / `RoundRect` 面板按钮 r=8、badge r=13 / `DrawTextW` / `DrawPanel` :1797）
  → 末尾 `BitBlt` 上屏（:3617）。**零 D2D / 零 GDI+ / 零分层窗口 / 零 DWM 属性调用。**
- cfg `tools/r3shieldcore_cfg.cpp`：同构（自绘面板 + 原生控件混排，单文件编译）。
- 链接库（`build_cfgtool.sh:141`）：`gdi32 user32 comctl32 kernel32 shell32 advapi32 comdlg32`。
  **加 D2D 需补 `d2d1.lib`（可能还有 `dxguid.lib`）；主程序 build.sh 同步。**

### 2.2 窗口样式（主程序 `:4349-4361`）

- `WS_OVERLAPPED | WS_CAPTION | WS_SYSMENU | WS_MINIMIZEBOX | WS_THICKFRAME`
  + `WS_EX_APPWINDOW | WS_EX_TOPMOST`（安全控制台常置顶）。
- **结论：保留标准标题栏**（Win11 Mica 应用也保留 caption，先只做客户区玻璃；
  自绘标题栏涉及 NC 区命中测试/拖拽/贴靠，列为远期不做）。

### 2.3 颜色体系：~35 个硬编码 COLORREF（`:135-170`）

浅色主题（底 250/250/250、面板白、40+ 语义色：拦截红/替换紫/各事件来源色）。
毛玻璃化必须把这套"颜色常量"升级为**材质参数表**（底色 + alpha + 高光 + 描边 + 噪点）。
按铁律 127（常量只此一处）：放 `shared/r3shieldcore/ui_material.h`，两 exe 共用
（cfg 的 include 路径已在 `build_cfgtool.sh:105-107`）。

### 2.4 刷新特性

- ARK 页定时器 300ms `InvalidateRect` 全屏重绘（MEMORY-3 v62）⇒ **背景模糊必须缓存化**，
  否则 300ms × 全屏高斯模糊。
- `WM_ERASEBKGND`：现有代码第一步就 `FillRect` 不透明底（`ColorBackground`）⇒ 这是
  "加了模糊却看不见"的第一成因，必须改为先 `BitBlt` 背景缓存再画内容。

### 2.5 原生控件（cfg，最大兼容痛点）

- 高级页原生 EDIT（v78 起，IME 刚需）、日志页下拉框 `IDC_LOGCOMBO`、若干按钮；
  `WM_CTLCOLOREDIT` 已处理（v78：白底深字）。
- 系统主题绘制的控件在毛玻璃上 = **实心补丁**。取舍见 §5.3。

### 2.6 DPI

`PerMonitorV2`（`rsrc/compatibility.manifest:20`）⇒ 捕获屏幕源要按物理像素换算
（`GetDpiForWindow` + 窗口矩形的物理坐标），背景缓存随 `WM_DPICHANGED` 失效。

## 3. 背景模糊：三条候选路径

### 3.1 方案 A：DWM 系统级 acrylic（零渲染成本）

- API：`DwmSetWindowAttribute(hwnd, DWMWA_SYSTEMBACKDROP_TYPE, …)`（Win11 22000+，已文档化，
  Mica/MicaAlt/Acrylic）；或 `SetWindowCompositionAttribute` +
  `ACCENT_ENABLE_ACRYLICBLURBEHIND`（Win10 1803+，未文档化但生态事实标准）。
- 机制：DWM 合成器直接对窗口后方做模糊 + tint，GPU 合成，**每帧成本 ≈ 0**。
- 局限（社区 2025-2026 实证）：
  - tint 只有一个 `GradientColor`，无高光/边缘光/内阴影/动效（§1.2 五个要素全无）；
  - 窗口语义不满足时（有 caption 的组合、部分 25H2 版本）**静默降级/不生效**；
  - GDI 不透明 `FillRect` 直接盖掉模糊 ⇒ 需改半透明绘制路径（本次无论如何都要改）。
- 定位：**Phase 0 对照基线**，或最终产品的"零成本兜底模式"。

### 3.2 方案 B-a：自绘 D2D 1.1 真高斯模糊（GPU，效果上限）

⚠️ **关键修正（本预研最重要的技术发现）**：
`ID2D1DCRenderTarget`（能渲染进 GDI HDC、看起来最适合本项目的那个接口）是
**D2D 1.0 接口，不支持 `CreateEffect`**——高斯模糊挂不上去（2026-10 核对 MSDN + 社区实证）。
`CLSID_D2D1GaussianBlur` 必须走 **D2D 1.1 DeviceContext** 链路：

```
D3D11CreateDevice → IDXGIDevice → D2D1CreateDevice → ID2D1DeviceContext
  → CreateCompatibleRenderTarget（离屏）
  → 画入捕获的屏幕位图 → CreateEffect(GaussianBlur, σ) → DrawImage
  → GetBitmap → ID2D1Bitmap1::Map(CPU_READ) → memcpy 进 32bpp DIB
  → BitBlt 当窗口背景（沿用 PaintWindow 现有结构）
```

- 性能：1024×740 模糊 GPU 1-3ms；CPU 回读（Map+memcpy）~1-2ms；刷新限频 8-10fps 时无感。
- 代价：链接加 `d2d1.lib` + `dxguid.lib`（主程序/cfg 两处）；设备丢失按
  `D2DERR_RECREATE_TARGET` 重建（成熟模式）；管线代码约 +150 行。
- 风险：多一层 D3D11 依赖；虚拟显卡/远程会话（RDP）上 D3D11 可能软件回退（变慢但不挂）。

### 3.3 方案 B-b：CPU 可分离 box blur（纯 GDI，零新依赖）

- 捕获 → 32bpp DIB → **可分离 box blur ×3 趟**（三次 box ≈ Gaussian，标准 stack-blur 技巧）。
- 1024×740 ≈ 758k px：3 趟 ≈ 4.5M 次乘加 ≈ **3-8ms/帧**（单线程，SSE 可再快）；
  8-10fps 限频刷新完全够用，**静止窗口 0 开销**。
- 质量：box×3 视觉接近高斯（无硬件时 Rainmeter 等软件的成熟做法）；无 GPU 依赖、
  无设备丢失、无链接变更。
- 定位：**性价比最高的主路线候选**。

### 3.4 方案 C：GDI 缩放近似（最廉价，质量最差）

`StretchBlt` 缩到 1/8 再拉回 = 双线性软模糊，单趟 <1ms。块感明显、有色带，
仅作"零成本兜底"或 B-b 之前的临时预览，不作正式路线。

### 3.5 方案 D：DirectComposition backdrop brush（不推荐）

`IDCompositionDevice` + `CreateBackdropBrush` 是 WinUI acrylic 的底座，但要把窗口
挂进 DComp visual tree、内容走 swapchain——与现有 GDI 自绘内容混合等于重写渲染层，
改造量最大。**不推荐**。

### 3.6 对比表

| 维度 | A DWM | B-a D2D GPU | B-b CPU box | C 缩放近似 | D DComp |
| --- | --- | --- | --- | --- | --- |
| 液态玻璃要素 | 无 | 无（玻璃层自绘补） | 同 | 同 | 无 |
| 模糊质量 | 好 | 最好（真高斯） | 良（box×3） | 差 | 好 |
| 静止成本 | 0 | 0 | 0 | 0 | 0 |
| 移动时/帧 | 0 | ~4ms | ~8ms | <1ms | 0 |
| 新依赖 | 无（未文档化 API） | d2d1+dxguid+D3D11 | 无 | 无 | 全链路 |
| 兼容风险 | 版本静默降级 | RDP/虚拟显卡软件回退 | 无 | 无 | 高 |
| 改动量 | 小 | 中（+150行管线） | 小（+80行） | 极小 | 大 |
| 定位 | 对照/兜底 | 效果上限 | **主候选** | 临时预览 | 不推荐 |

## 4. 液态玻璃层：绘制模型（无论背景选哪条路都要做）

每帧 `PaintWindow` 的绘制顺序（替换现有"先填不透明底"的第一步）：

```
┌────────────────────────────────────────────────┐
│ L4 内容层  文字/表格/图标（深色，可读性优先）      │  GDI 画进内存 DC
│ L3 控件层  tab / 按钮：玻璃材质 + hover 高光      │
│           按下：高光收缩 + 缩放 0.98              │
│ L2 玻璃面  每面板：RoundRect 白 α 55-72%          │
│           + 1px 内描边（白 α35%）                 │
│           + 上缘内侧高光渐变（白 α50→0，2px）       │
│           + 底部内阴影（黑 α6%）                   │
│           + 噪点（α2%）                            │
│ L1 底染色  AlphaBlend 白 α~10% 满客户区           │
│ L0 背景    BitBlt(模糊后的屏幕)——失效才重建        │
└────────────────────────────────────────────────┘
              ↓ BitBlt 上屏（沿用现有 :3617，不动）
```

- L2/L3 的 alpha 填充用 `AlphaBlend`（32bpp DIB 双缓冲，需把现有 `CreateCompatibleDC`
  的内存位图换成显式 32bpp DIBSection——一次小重构）。
- 表格斑马纹从 `FillRect` 实色改为 AlphaBlend 叠加（否则斑马纹下面看不到模糊）。
- 高光方向 = 鼠标位置与面板中心的单位向量点积，spring 插值 ~150ms（L3 才需要；
  静态展示版可先不做 5 号要素）。
- 内容层文字色不变（深字在浅色半透明玻璃上可读性 OK；这是"可读性优先"的取舍）。

## 5. 关键约束与坑（本项目特有）

### 5.1 模糊源自捕获：置顶窗口的"自我反馈"（最大技术坑）

主程序 `WS_EX_TOPMOST`（安全控制台语义）⇒ 屏幕捕获会把**自己上一帧**也抓进来
⇒ 移动窗口时模糊源是"自己的残影"，来回拖会累积失真。

候选解法（Phase 0 实测哪个稳）：

1. **`SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE)`**：捕获期间临时把自身
   从屏幕捕获里剔除（屏幕录制器的标准做法），捕获完恢复 `WDA_NONE`。Win10 2004+ 可用。
   注意：切换可能触发 DWM 重算，需测稳定性与耗时。
2. **限频 + 接受反馈**：移动时背景缓存 8-10fps 刷新（窗口没动就不刷），静止后一帧
   收敛。反馈只在拖动态可见，多数玻璃软件（历史先例）就是这么干的。
3. **静止快照**：只在窗口静止 ≥N ms 后刷新一次背景，拖动态保持上一张。
   最省但拖完有个"刷新滞后"。

### 5.2 验证链重校（铁律 24/209/249）

- 探针截图必须走**屏幕 DC `BitBlt`**（现有 `gui_preview_probe` 已是）——**不能**用
  `PrintWindow`（DWM/半透明窗口的静态缓存帧不可靠，铁律 24 同款坑）。
- 毛玻璃改变像素分布：`非白>3%`、`紫>0`、尺寸判据等指纹**全部要按新基准图重新校准**，
  且每个新判据**配负对照**（铁律 209/249：裸 `grep -qF` 被子串满足 = 恒真）。
- 铁律 254/266/267（探针进程清理/互斥体/相对路径）不受影响，继续沿用。

### 5.3 原生控件补丁（cfg）

| 控件 | 取舍建议 |
| --- | --- |
| 按钮（含"立即同步"等） | **全部自绘**（已有自绘按钮体系：HeaderAction 一套 id 喂绘制+命中，铁律 30） |
| 高级页 EDIT（IME 刚需） | **保留原生 + 浅色不透明底**（可读性优先；透明 EDIT 在 Win32 很难做好，投入产出比低） |
| 日志页下拉框 `IDC_LOGCOMBO` | 同 EDIT：原生 + 浅色底，或改自绘下拉（待定，见 §7.3） |

原则：**原生控件当"不透明内容"处理，玻璃层绕开它们**——比硬啃透明控件稳得多。

### 5.4 其他必须一并处理的

- `WM_ERASEBKGND` + 首帧不透明底：改为先 BitBlt 背景缓存（§2.4）。
- `WM_SIZE` / `WM_DPICHANGED`：背景缓存失效重建；布局函数
  （`ArkLayoutFor` / `AdvLayoutFor` 同源绘制命中，铁律 127）不动。
- 置顶窗口压在**全屏视频**上：模糊源每帧都在变 ⇒ 刷新限频 + 按
  `WM_DISPLAYCHANGE`/壁纸变更事件刷新（备选：检测大面积变化触发刷新）。
- GBK 闸门（铁律 244）：新增符号必须 CP936 内有（`√ × ●` 这类已验证可用），
  注释豁免按闸门输出的行号精确给（v79 踩过"按字符匹配连累注释"的坑）。
- 链接变更：cfg 链接行（`build_cfgtool.sh:141`）与主程序 build.sh 同步加库；
  多架构脚本两架构都真编（铁律）。
- ABI：纯 UI，`AbiVersion=26` 不变，ini 键不动，引擎 DLL 不参与，共享内存不动。

## 6. 推荐路线（分阶段，每阶段独立验收）

### Phase 0 —— 探针（≈0.5 天，不接生产）

独立 demo exe（严守 `--gui-preview` 纪律：建窗不初始化引擎、不注入）：

- 最小 Win32 窗口 + 32bpp DIB 双缓冲 + 屏幕捕获 + 三选一模糊（A / B-a / B-b）
  + 半透明面板（L0-L2 层）。
- 实测三件事：
  1. **DWM acrylic** 在现有窗口样式（caption + TOPMOST）下到底生不生效、视觉如何；
  2. **`WDA_EXCLUDEFROMCAPTURE` 自剔除**是否稳定（决定 B 的捕获策略，§5.1）；
  3. B-a / B-b 的实际帧成本（本机含 GPU 型号、RDP 降级路径）。
- 产出：三张对比截图 + 帧耗时表 ⇒ 拍定主路线。截图走 `gui_preview_probe`
  同款 BitBlt 断言。

### Phase 1 —— 材质体系（纯重构，视觉零变化）

`shared/r3shieldcore/ui_material.h`（单一真源，铁律 127）+ COLORREF → 材质参数。
先过现有全部门禁（GBK 窄/宽 + 负对照），确保重构本身无回归。

### Phase 2 —— 主程序背景模糊

`PaintWindow` 改：背景缓存 + AlphaBlend 内容；`WM_SIZE/DPICHANGED` 失效；
玻璃层 L0-L2。逐页签截图核对（沿用 `test_gui_preview.sh` 规格）。

### Phase 3 —— 面板/tab/按钮玻璃化（L3）

`DrawPanel` / tab / `HeaderAction` 逐个换材质 + hover 高光（含鼠标方向）。
**每步截图核对**（v77/v78 教训：只有截图看得出的缺陷占多数）。

### Phase 4 —— cfg 同步

同 Phase 2-3 + §5.3 原生控件取舍落地（按钮自绘 / EDIT 浅色底 / 下拉框待定）。

### Phase 5 —— 验证链与发布

探针判据按新基准图重校 + 负对照；`test_gui_preview.sh` 规格更新；
发布包过铁律 117 残留清单 + `deploy_dist.sh` 全节。

### 降级预案

Phase 0 若自剔除不稳或帧成本超标 ⇒ **降级为"壁纸源静态毛玻璃"**（模糊源取桌面壁纸/
纯色渐变而非实时屏幕，零捕获问题）+ 玻璃层照做。视觉完成度 ~70%，风险≈0。
亦可整窗退化为方案 A（DWM acrylic）+ 玻璃层，作"低配机兜底"。

3. **cfg 下拉框**：接受原生控件"实心补丁"，还是投入子类化自绘？
4. **模糊源优先级**：实时屏幕（效果真，有自我反馈坑）vs 壁纸源（零坑，跨窗口失真）
