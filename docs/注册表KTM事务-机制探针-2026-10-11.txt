# 0. 结论摘要（先看这个）
################################################################
[结论 1] 三个事务导出在本机 ntdll 里都存在、都能被 MinHook 挂上，
         且与对应的非事务导出是**不同的函数**（syscall 号也不同）：
             NtOpenKey               addr=...5A2000  ssn=18
             NtOpenKeyEx             addr=...5A4310  ssn=299
             NtOpenKeyTransacted     addr=...5A4330  ssn=300
             NtOpenKeyTransactedEx   addr=...5A4350  ssn=301
             NtCreateKey             addr=...5A2160  ssn=29
             NtCreateKeyTransacted   addr=...5A3470  ssn=182
         => "补挂这三个"不是重复劳动，是**真的补了一块**。

[结论 2] ★★ 缺口成立：把事务 detour 关掉（＝修复前），
         `NtOpenKeyTransacted(KEY_SET_VALUE)` 打开受保护键**能拿到句柄**；
         而且**非事务那条 `NtOpenKey` detour 完全没有被顺带触发**
         （hits 3 -> 3）—— 说明事务变体**不是**内部转发到 `NtOpenKey`。
         => 原来"写不进 / 读不到 / 看不见"的**第一道门（准入）形同虚设**。

[结论 3] ★★ 修复生效：打开事务 detour 后，三个导出对受保护键的写打开
         一律 `0xC0000022 STATUS_ACCESS_DENIED`；
         同时**负对照通过**（不受保护的键仍然放行）—— 是"准入判据"而不是"一律拒绝"。

[结论 4] ★★ "缺的只是准入"这句话成立：
         事务键句柄上真调 `NtQueryValueKey` / `NtEnumerateKey` / `NtSetValueKey`
         **全部走到同一个 detour**（与调用方视角一致），并且
             v71 值替换生效（数据区全 0、长度字段不动）
             v72 枚举隐藏生效（HiddenChild 被跳过：0 -> Vis1、1 -> Vis2、
                              索引 2 -> 0x8000001A NO_MORE_ENTRIES）
         非事务句柄上结果**逐字节相同**。

[结论 5] ★ 生产 v72 不会在事务句柄上静默降级：
         `NtQueryKey(事务键句柄, KeyNameInformation)` **能拿到路径**
         （事务 91 字符 / 非事务 91 字符，完全一致），
         所以 `ResolveKeyPath` 这条路在事务句柄上照样通。
         探针里"枚举 detour 取不到父路径的次数 = 0"。

[结论 6] 事务语义实测：**读己之写成立**（事务内写 0x55667788，事务内读回同值）；
         `RollbackTransaction` 后该值 `0xC0000034 OBJECT_NAME_NOT_FOUND`（回滚干净）；
         对照事务 `CommitTransaction` 后 `0x0BADF00D` 读得到（写确实落地）。

[坑位 A] ★★ `NtOpenKey` / `NtOpenKeyTransacted` **不接受预定义伪句柄**
         （`HKEY_CURRENT_USER` / `HKEY_LOCAL_MACHINE` / `HKEY_USERS`）作为
         `RootDirectory` => 一律 `0xC0000008 STATUS_INVALID_HANDLE`。
         `RegOpenKeyExW(HKEY_CURRENT_USER, ...)` 能跑，是因为 **advapi32 自己
         把伪句柄换成了真句柄** —— 这掩盖了上面的坑（本探针第一版就栽在这里，
         全部用例报 0xC0000008）。
         => Nt* 这条路只能用：① `RootDirectory = 真键句柄` + 相对名；
            ② `RootDirectory = NULL` + **绝对 NT 路径**。
         （生产 `registry_guard.cpp` 不构造 ObjectAttributes，所以**不受影响**；
           但真实调用方会走这两种形态之一。）
