# R3 ShieldCore 主程序 —— 怎么开启「拦截」（速查）

> 这是**上手速查**，不是完整手册。
> 深度说明在发布包里：`部署指南.md`（部署/验证/停止）、`模式选择说明.md`（五种模式）、
> `配置详解.md`（每个开关的判据与盲区）。
>
> 本文只回答一件事：**拿到 `dist/R3ShieldCore-x64/` 之后，怎么让它真的拦东西。**

---

## 0. 30 秒版

```
① 改配置：mode=block           （本包出厂值，通常不用动）
② 起引擎：双击 start.bat        （它会自己弹 UAC 提权）
③ 看效果：同目录 r3shieldcore-events.log 里有 BLOCK 行 = 真的拦住了
④ 停引擎：双击 stop.bat         （或直接关掉那个控制台窗口）
```

⚠️ **出厂就是 `mode=block`** —— 拷过去双击 `start.bat` 就已经在拦了，
**不需要先配置**。下面几节是"想改 / 想看 / 想确认"时才需要。

---

## 1. 改的是哪一份 ini？（决策树）

引擎**优先**读 ProgramData 那份，读不到才回退 exe 同目录：

```
%ProgramData%\R3 Shield Core\r3shieldcore.ini   ← 安装包装的：优先读这份
        ↓ 不存在（绿色包 / 旧安装 / 直接拷文件夹）
<exe 所在目录>\r3shieldcore.ini                  ← 回退读这份
```

| 你的部署方式 | 该改哪份 |
|---|---|
| 跑了 `R3ShieldCore-Setup.exe` 安装 | `%ProgramData%\R3 Shield Core\r3shieldcore.ini` |
| 直接拷 `R3ShieldCore-x64` 文件夹（绿色包） | `<那个目录>\r3shieldcore.ini` |

> ★ 实测判断法：起引擎后看 `r3shieldcore-console.log` 里的
> `配置文件 : <路径>` —— 那一行就是**引擎真正在读**的那份，别猜。

**不想手改文本**：双击 `r3shieldcore-cfg.exe`（**不需要管理员**）。
它把 ini 做成表单，带范围校验；保存时**只改你动过的那几行**，
中文注释和被注释掉的示例原样保留。它读写的就是上面那份**生效的** ini。
改完**重启引擎**才生效。

## 2. 最小配置：开启「拦截」

```ini
mode=block
```

就这一行。`block` = 主动防御：只拦**高置信度的高危行为**
（持久化落点 / 劫持 / 凭据 / hive 级 / 裸盘引导区），正常程序照用。

| 想干什么 | 写什么 |
|---|---|
| 先只观察、不拦（摸噪音） | `mode=log` |
| **正常拦截（日常推荐）** | `mode=block` ← 出厂值 |
| 拦下来弹窗问你 | `mode=ask` |
| 全拦（★ 会把程序拦到打不开，只用于隔离/取证/演示） | `mode=block_all` 或 `block_all_safe` |
| **只想让某一个进程被监控**（开发机安全跑法） | `mode=block` + `test_inject_only=<镜像名>` |

### 2.1 想拦得更全：连「文件写」也一起拦

出厂 `hook_file=0`（文件面比注册表热得多，默认关）。要开就把预设覆盖过去：

```
把 r3shieldcore-block.ini 复制 -> 改名成 r3shieldcore.ini（覆盖生效的那份）-> 重启引擎
```

它与默认的**唯一区别**就是 `hook_file=1`。

### 2.2 想「读不到 / 看不见」而不是「写不进」（v71/v72）

```ini
protect_reg=Software\MyCompany\Critical   # ★ 触发面：只认这个名单
spoof_reg=1        # 读上面命中的键 -> 成功但数据区全 0（"读到了，但是空的"）
spoof_reg_enum=1   # 枚举上面命中的键 -> 命中保护前缀的子键/值直接消失
```

> ⚠️ **必须配 `protect_reg=` 才有效** —— 名单为空时这两个开关一个字节都不会动。
> ⚠️ 触发面**只认 `protect_reg`**，不认内置高危表。

### 2.3 不想动真机？——「限定注入范围」（v69，开发机安全跑法）

```ini
mode=block                       # 拦截行为
test_inject_only=my_app.exe      # 注入范围：只注这一个（可重复写多行，上限 16）
```

★ **两件事是解耦的**：名单管「注入谁」，`mode=` 管「拦不拦」。
所以 `mode=block` + 名单 = **只注入目标、并在它身上真拦真记**。
名单之外的进程**一个 hook 都不挂**。

## 3. 怎么启动

```
双击 start.bat            ← 推荐（脚本自己弹 UAC 提权）
   或  右键 R3 ShieldCore.exe -> 以管理员身份运行
   或  直接双击 R3 ShieldCore.exe（清单是 requireAdministrator，会弹 UAC）
```

★ **必须提权** —— 引擎清单里写死了 `requireAdministrator`。
不起管理员，它连启动都做不到（UAC 会拦在门口）。

`start.bat` 依次做：① 检查目录可写性 → ② 启动引擎 → ③ 等 3 秒确认存活；
任一步失败都会停下来并说明原因。

**成功的标志**：那个**控制台窗口保持打开** = 引擎在跑。

> ⚠️ **引擎已经在跑时，`start.bat` 会直接退出**（v45 的刻意顺序）——
> 脚本提权要调 `powershell.exe`，而它在 System32 高危名单里，
> 会被引擎自己拦掉。所以"引擎运行中 → 脚本不能自己提权"是设计使然，不是 bug。

## 4. 怎么确认它**真的在拦**（三个证据，缺一不可）

| # | 看什么 | 期望 |
|---|---|---|
| ① | `r3shieldcore-console.log` | 出现 **`注入新进程: N 个`** —— 只有横幅、没有这行 = 引擎起来了但**一个 hook 都没装** |
| ② | `r3shieldcore-console.log` | `配置文件 : <路径>` 是你**想改的那份**、`模式 : BLOCK` |
| ③ | `r3shieldcore-events.log` | 有新事件在滚；触发一个测试操作（比如改注册表自启动项）应出现 **`BLOCK`** / `[HIGH-RISK]` |

界面里也能看：`r3shieldcore-cfg.exe` 的「日志」页签实时跟随，
高危标品红、被拦标红。

> ★ 三个日志都在 **exe 同目录**（不是 ProgramData）：
> `r3shieldcore-console.log`（引擎诊断）/ `r3shieldcore-events.log`（事件）/ `r3shieldcore-stats.json`（计数）。

---

## 5. 怎么停

```
双击 stop.bat                 ← 会自动提权；也可右键 -> 以管理员身份运行
   或  直接关掉引擎的控制台窗口
   或  dskill.exe <引擎PID>
```

> ⚠️ 引擎正在跑时 `stop.bat` 可能提示"无法自动提权" —— 同上（v45），
> 改用**右键 → 以管理员身份运行**，或直接关窗口。

## 6. 先看不跑引擎的「效果」（合规、零风险）

引擎的正常工作是**全局注入**所有非系统进程（包括你正在用的编辑器），
所以本项目有一条硬约定：**不在开发机上随手跑引擎**。
想先"看见效果"又不想冒这个风险，有三条路：

| 方式 | 命令 | 说明 |
|---|---|---|
| **机制演示**（不注入、不跑引擎） | `bash build_ktm_effect_demo.sh --run` | 三幕：保护关 / 保护开 / 事务绕过。真实输出见 `docs/注册表保护-效果演示-2026-10-11.txt` |
| **替换 API 结果控制台**（不注入、不跑引擎） | `bash build_spoof_console.sh --run` | 交互式：**进「高级模式」要先答对 3 道 Win32 题**（全对才开门）。默认 = 保护开 + 三个替换全开 ⇒ 一进来 `attack all` 就是「替换生效」的样子；`compare all` 把同一个面的**三种状态并排**打出来。真实输出见 `docs/替换API结果-高级模式控制台-2026-10-11.txt` |
| **真引擎端到端**（限定注入，需管理员） | `bash tools/spoof_e2e.sh --prepare` → 管理员终端 `bash tools/spoof_e2e.sh --run-engine` | 真启动引擎、只注入一个测试目标，三格矩阵一次验「拦截 + 替换」。**A 格就是纯拦截的实证**（屏幕被拒 / 剪贴板被拒 / 注册表读到真值） |

★ `spoof_e2e.sh --run-engine` 自带**冒烟闸门**：先用 9 秒证明
"白名单真的限住了注入范围"（判据 = 引擎自报 `注入新进程: N 个`，1 ≤ N ≤ 5），
**这一级不过就不跑三格矩阵** —— 避免白名单失效时变成全局注入。
